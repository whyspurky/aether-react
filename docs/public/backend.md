# backend

rust сторона приложения, http запросы, воспроизведение звука, управление zapret

## структура

*api* soundcloud api и hls

*audio* воспроизведение

*zapret* управление zapret

*shortcuts* медиа клавиши

*lib* регистрация команд и плагинов

## api

разбит на модули

*client* http клиент, прокси, retry, fetch

*hls* скачивание hls

*soundcloud* поиск, метаданные, популярное, моя волна, плейлисты

*stream* выбор формата и получение url стрима

### http клиент

один клиент на всё приложение

браузерный *user agent* чтобы soundcloud не резал запросы

есть два таймаута

1. *connect timeout* 5 секунд, если tcp не установился за 5 секунд ошибка

2. *timeout* 10 секунд, весь запрос включая чтение body

### что умеет

*поиск* треков, плейлистов, артистов

*метаданные* треков, артистов, плейлистов

*популярное* подборка на основе открытых данных

*моя волна* рекомендации из истории прослушиваний

*плейлисты* с полной загрузкой всех страниц

*url стрима* финальный url для воспроизведения

### как работает популярное

настоящего топа soundcloud не существует как api
поэтому используется список *захардкоженных артистов*
по ним идёт *round robin*
для каждого берётся *первый подходящий* трек

*фильтры*

1. длительность от 30 секунд до 10 минут

2. не дубликаты по id

не идеально, но даёт приемлемую подборку

### как работает моя волна

1. берётся история прослушиваний

2. для каждого артиста из истории загружаются его треки

3. треки раскладываются *по корзинам*, одна корзина на артиста

4. потом *чередуются* по одному треку из каждой корзины, пропуская дубликаты

5. цель 50 треков

6. если пусто, фолбэк на поиск по слову new

получается *микс* по треку от каждого артиста которого ты слушал

### hls стриминг

soundcloud отдаёт треки двумя способами

1. *progressive* это прямой mp3 или aac файл

2. *hls* это плейлист из фрагментов

порядок выбора такой

1. сначала *aac 160*

2. потом *aac 96*

3. потом *mp3*

4. потом *progressive* как fallback

как работает для hls

1. master плейлист содержит ссылки на медиа плейлисты с разным bitrate

2. выбирается *лучший bitrate*

3. медиа плейлист содержит ссылки на *сегменты*

4. все сегменты *скачиваются параллельно*

5. *склеиваются* в один буфер

6. лимит *200 мегабайт* на трек

после склейки буфер отдаётся декодеру, который декодирует из памяти
декодер думает что это обычный локальный файл и играет нормально

### проверка подключения

разделена на две части чтобы проверять параллельно

1. *api* проверяет доступность главного api soundcloud

2. *cdn* проверяет доступность cdn откуда идёт звук

### прокси

http клиент пересоздаётся при смене прокси
старые запросы завершатся на старом клиенте, у каждого свой

## zapret

обход блокировок через утилиту zapret

### что умеет

*проверять статус* работает ли zapret сейчас

*запускать* через службу или через bat стратегии

*останавливать* через службу или убийство процесса

*сканировать папку* находит все стратегии general bat

*проверять списки* на наличие доменов soundcloud

*добавлять домены* около 20

*скачивать* последний релиз с гитхаба и распаковывать

## audio

всё воспроизведение
разделено на три файла

1. *state* для данных

2. *engine* для логики

3. *mod* для команд

### state

структура *Playback* хранит всё состояние плеера

1. играет ли сейчас

2. замучен ли

3. громкость

4. позицию

5. длительность трека

6. байты текущего трека для сика

структура *AppState* контейнер с лок обёртками

1. player это движок rodio

2. playback это состояние

создаётся один раз при старте приложения

### engine

*воспроизведение* это загрузка и старт

1. если url hls, качает целиком

2. если progressive, качает напрямую

3. декодирует байты

4. запускает player

5. обновляет состояние

*пауза, возобновление, стоп* это прокси к движку

*сик*

1. берёт байты и длительность

2. клампит позицию в ноль и duration

3. создаёт новый декодер из тех же байтов

4. пробует сикнуть

5. если сработал, играем с позиции

6. если нет, играем с начала, некоторые форматы не поддерживают сик

7. пересоздаёт движок

8. записывает реально применённую позицию

### mod

просто команды которые зовут функции из engine
